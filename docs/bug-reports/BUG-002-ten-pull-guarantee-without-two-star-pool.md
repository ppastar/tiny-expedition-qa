# BUG-002 [모집/데이터] 2성 확률 0% + 2성 후보 없음 배너가 데이터 검사를 통과하고, 10연 모집이 대부분 실패함

> **구분: 실제 결함 (열림)** — [모집 기획 리뷰](../spec-review/gacha.md) 중 BUG-001을 다시 재현하다가 찾았습니다. 아래 출력은 현재 코드(`1db01a0`)와 수정 전 코드(`15562c3`)에서 실제로 돌린 결과입니다. 수정은 별도 PR로 합니다.

| 항목 | 내용 |
|---|---|
| 상태 | 열림 |
| 심각도 | Major — 해당 데이터가 들어가면 그 배너의 10연 모집이 대부분 막힘 (보석은 안전) |
| 우선순위 | P1 — 지금 실제 데이터(`banners.json`)의 두 배너는 2성 후보가 있어 발생하지 않음. 검사기 구멍이라 다음 데이터 작업 전에 막아야 함 |
| 영역 | 모집 / 기획 데이터 검사 |
| 발견 커밋 | `1db01a0` (현재 main) — `15562c3`부터 있었음 |
| 관련 TC | 없음 → **DATA-010 추가 후보** ("10연 보정이 켜진 배너에 2성 후보가 없으면 Error") |
| 관련 이슈 | [BUG-001](BUG-001-gems-taken-on-failed-pull.md) |

## 사전조건

배너 `b_test`:

- 3성 2.5% (250bp) / **2성 0%** / 1성 97.5% (9750bp) — 합계 100%
- **2성 후보 목록 비어 있음**
- 10연 보정(`TenPullGuarantee`) **켜짐**, 천장 90
- 보석 1500

"2성이 안 나오는 배너니까 2성 후보도 비워 둔다"는, 기획 데이터에서 충분히 나올 수 있는 설정입니다.

## 재현 절차

1. 위 배너로 `DataValidator.Validate`를 돌린다.
2. 시드 1~100 각각에 대해 새 세션(보석 1500)을 만들고 `b_test` 10회 모집을 요청한다.
3. 성공/실패 횟수와 보석을 센다.

## 기대 결과

- 1번에서 **Error**: "10연 보정이 켜져 있는데 2성 후보가 없습니다" — 빌드 전 훅에서 막혀야 함.
- 또는 (기획이 그렇게 정한다면) 2성 후보가 없을 때 보정이 3성으로 올라가는 등 정해진 동작.

## 실제 결과

| | 현재 코드 `1db01a0` | 수정 전 `15562c3` |
|---|---|---|
| 데이터 검사 | **Error 0건** (Warning 1건: "천장이 있는데 천장 포함 실제 3성 확률이 공시되지 않았습니다") | **Error 0건** |
| 10연 모집, 시드 1~100 | 성공 24 / **DataError 76** — 보석은 그대로 | 성공 24 / **예외 76 — 76번 모두 보석 1500이 빠지고 결과 없음** |

앞 9장이 모두 1성이면 10번째 장에 "2성 이상" 보정이 걸리는데, 2성 후보가 없어 뽑기가 실패합니다. 1성이 97.5%이므로 앞 9장이 모두 1성일 확률은 0.975⁹ ≈ 79.6%이고, 관측 76/100은 이 값과 어긋나지 않습니다.

즉 **BUG-001은 데이터 검사를 통과하는 데이터로도 터질 수 있었습니다.** BUG-001 수정 덕분에 지금은 보석이 빠지지 않지만, 사용자는 "모집 데이터 오류로 모집할 수 없습니다" 토스트를 보고 10연을 거의 할 수 없습니다.

## 재현율

시드 1~100 중 76 (현재·수정 전 모두 같은 시드에서 같은 결과).

## 첨부

### 재현 코드 (임시로 넣고 실행, 저장소에는 넣지 않음)

```csharp
var banner = TestData.Banner(250, 0, 9750);    // 3성 2.5% / 2성 0% / 1성 97.5%
banner.Pool[Rarity.TwoStar].Clear();
banner.TenPullGuarantee = true;
var db = TestData.Db(new[] { banner });
var issues = DataValidator.Validate(db);         // → Error 0
for (ulong seed = 1; seed <= 100; seed++)
{
    var s = new GameSession(db, new PlayerState { Gems = 1500 });
    s.Reseed(seed);
    var r = s.Pull("b_test", 10);                // 현재: r.Error == DataError 76번
}
```

### 실행 출력

```
# 1db01a0
validator issues for b_test = 1 [Warning] banners/b_test: 천장이 있는데 천장 포함 실제 3성 확률이 공시되지 않았습니다.
seeds 1..100: ok=24 dataError=76

# 15562c3
validator errors = 0
old seeds 1..100: ok=24 gemsLostNoResult=76
```

## 원인

- `DataValidator`는 **확률이 0보다 큰 등급**에 대해서만 후보 목록이 비었는지 검사합니다 (`kv.Value > 0 && pool.Count == 0`).
- 그런데 `GachaService`의 10연 보정은 2성 확률과 상관없이 1성을 **2성으로 바꿔** 2성 후보에서 뽑습니다.
- 두 규칙이 서로를 가정하지 않아 생긴 틈입니다.

## 제안 (기획 확인 필요)

1. 검사기에 규칙 추가: `TenPullGuarantee`가 켜져 있으면 2성 후보가 1명 이상이어야 함 → Error. TC DATA-010 추가.
2. 기획 질문: 2성이 없는 배너에서 10연 보정은 어떻게 동작해야 하나? (보정 끄기 / 3성으로 올림 / 2성 후보 필수) → [기획 리뷰 Q8](../spec-review/gacha.md)
3. 뮤테이션 스모크에 "보정 대상 후보 검사 누락"을 넣어 DATA-010이 잡는지 확인.
