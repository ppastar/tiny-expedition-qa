# BUG-002 [모집/데이터] 2성 확률 0% + 2성 후보 없음 배너가 데이터 검사를 통과하고, 10연 모집이 대부분 실패함

## 사전조건

배너 `b_test`:

- 3성 2.5% (250bp) / **2성 0%** / 1성 97.5% (9750bp) — 합계 100%
- **2성 후보 목록 비어 있음**
- 10연 보정(`TenPullGuarantee`) **켜짐**, 천장 90
- 보석 1500

"2성이 안 나오는 배너니까 2성 후보도 비워 둔다"는, 기획 데이터에서 충분히 나올 수 있는 설정입니다.

## 재현 절차

1. 위 배너로 `DataValidator.Validate`를 돌린다.
2. 시드 1~100 각각에 대해 새 세션(보석 1500)을 만들고 `b_test` 10회 모집을 요청한다.
3. 성공/실패 횟수와 보석을 센다.

## 기대 결과

- 1번에서 **Error**: "10연 보정이 켜져 있는데 2성 후보가 없습니다" — 빌드 전 훅에서 막혀야 함.
- 또는 (기획이 그렇게 정한다면) 2성 후보가 없을 때 보정이 3성으로 올라가는 등 정해진 동작.

## 실제 결과

| | 현재 코드 `1db01a0` | 수정 전 `15562c3` |
|---|---|---|
| 데이터 검사 | **Error 0건** (Warning 1건: "천장이 있는데 천장 포함 실제 3성 확률이 공시되지 않았습니다") | **Error 0건** |
| 10연 모집, 시드 1~100 | 성공 24 / **DataError 76** — 보석은 그대로 | 성공 24 / **예외 76 — 76번 모두 보석 1500이 빠지고 결과 없음** |

앞 9장이 모두 1성이면 10번째 장에 "2성 이상" 보정이 걸리는데, 2성 후보가 없어 뽑기가 실패합니다. 1성이 97.5%이므로 앞 9장이 모두 1성일 확률은 0.975⁹ ≈ 79.6%이고, 관측 76/100은 이 값과 어긋나지 않습니다.

즉 **BUG-001은 데이터 검사를 통과하는 데이터로도 터질 수 있었습니다.** BUG-001 수정 덕분에 지금은 보석이 빠지지 않지만, 사용자는 "모집 데이터 오류로 모집할 수 없습니다" 토스트를 보고 10연을 거의 할 수 없습니다.

## 재현율

시드 1~100 중 76 (현재·수정 전 코드 모두 76/100).

## 첨부

### 재현 코드 (임시로 넣고 실행, 저장소에는 넣지 않음)

```csharp
var banner = TestData.Banner(250, 0, 9750);    // 3성 2.5% / 2성 0% / 1성 97.5%
banner.Pool[Rarity.TwoStar].Clear();
banner.TenPullGuarantee = true;
var db = TestData.Db(new[] { banner });
var issues = DataValidator.Validate(db);         // → Error 0
for (ulong seed = 1; seed <= 100; seed++)
{
    var s = new GameSession(db, new PlayerState { Gems = 1500 });
    s.Reseed(seed);
    var r = s.Pull("b_test", 10);                // 현재: r.Error == DataError 76번
}
```

### 실행 출력

```
# 1db01a0
validator issues for b_test = 1 [Warning] banners/b_test: 천장이 있는데 천장 포함 실제 3성 확률이 공시되지 않았습니다.
seeds 1..100: ok=24 dataError=76

# 15562c3
validator errors = 0
old seeds 1..100: ok=24 gemsLostNoResult=76
```

## 원인

- `DataValidator`는 **확률이 0보다 큰 등급**에 대해서만 후보 목록이 비었는지 검사합니다 (`kv.Value > 0 && pool.Count == 0`).
- 그런데 `GachaService`의 10연 보정은 2성 확률과 상관없이 1성을 **2성으로 바꿔** 2성 후보에서 뽑습니다.
- 두 규칙이 서로를 가정하지 않아 생긴 틈입니다.

## 수정 방향 (결정)

후보는 셋이었습니다: ① 2성 후보 필수(검사기 Error) ② 2성 후보가 없으면 보정을 3성으로 올림 ③ 2성 후보가 없으면 보정 끄기. ([기획 리뷰 Q8](../spec-review/gacha.md))

**①로 정했습니다.** ②·③은 게임 규칙이 바뀌어 확률 공시("10연 2성 이상 보장", 천장 포함 실제 3성 확률)에 영향을 주지만, ①은 규칙을 그대로 두고 잘못된 데이터가 빌드에 들어오지 못하게 막습니다.

1. 검사기 규칙: `TenPullGuarantee`가 켜져 있으면 2성 후보가 1명 이상이어야 함 → Error "10연 보정이 켜져 있는데 2성 후보 캐릭터가 없습니다." (2성 확률이 0이어도 검사)
2. 모집 코드는 바꾸지 않음. 검사를 거치지 않은 데이터가 들어오면 지금처럼 `DataError`로 실패하고 보석·천장·보유를 건드리지 않음(BUG-001 수정) — 이것을 회귀 테스트로 고정.
3. 뮤테이션 스모크에 "10연 보정 대상(2성) 후보 검사 누락"을 넣어 DATA-010이 잡는지 확인.

## 수정 확인

| 확인 | 결과 |
|---|---|
| 회귀 TC DATA-010 추가 | 통과 (`TenPullGuaranteeWithoutTwoStarPool_IsError`: 이 배너 → "10연 보정" Error / 보정 끄면 없음 / 2성 후보가 있으면 없음) |
| GACHA-015에 이 배너 케이스 추가 | 통과 (`TenPullGuaranteeWithoutTwoStarPool_FailsWithoutSideEffects`: 시드 1~100 10연, 실패한 시드마다 DataError · 보석 3000 · 천장 5 · 보유 없음, 실패 1건 이상) |
| 뮤테이션 스모크 "10연 보정 대상(2성) 후보 검사 누락" | DATA-010이 검출 — 전체 17/17 |
| 전체 파이프라인 | `bash scripts/test-all.sh` 모든 단계 통과 — dotnet 테스트 74/74, 실제 데이터 검사 오류 0·경고 0, TC 61개 (Unity 미실행) |

수정 후 위 '재현 코드'를 다시 돌린 출력:

```
validator issues for b_test = 2
  [Error] banners/b_test: 10연 보정이 켜져 있는데 2성 후보 캐릭터가 없습니다.
  [Warning] banners/b_test: 천장이 있는데 천장 포함 실제 3성 확률이 공시되지 않았습니다.
seeds 1..100: ok=24 dataError=76 stateChangedOnFailure=0
```

- 검사기가 이제 이 배너를 **Error**로 잡습니다. 실제 데이터에서는 빌드 전 훅·CI의 `qa validate-data`에서 막힙니다.
- 모집 코드는 바꾸지 않았으므로, 검사를 거치지 않고 들어온다면 결과는 그대로 성공 24 / DataError 76입니다. 실패한 76번 모두 보석·보유가 그대로였습니다(`stateChangedOnFailure=0`). 즉 "10연이 되게" 고친 것이 아니라 "이런 데이터가 들어오지 못하게" 고쳤고, 들어오더라도 재화는 안전합니다.
