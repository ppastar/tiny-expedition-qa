# DEMO-001 [모집] 천장이 90번째가 아니라 91번째 모집에서 걸림

> **구분: 시연용 (일부러 넣은 결함)** — 실제 출시물의 버그가 아닙니다. [뮤테이션 스모크](../../scripts/mutation_smoke.py)의 "천장 off-by-one" 변경을 코드에 넣은 상태에서 도구·테스트를 돌린 출력입니다. "이런 결함이 들어오면 이렇게 리포트한다"는 예시입니다.

| 항목 | 내용 |
|---|---|
| 심각도 | Critical — 공시한 천장(90회)과 실제 동작이 다름. 확률형 아이템 정보 공개 위반 소지 |
| 우선순위 | P0 |
| 영역 | 모집 / 천장 |
| 관련 TC | GACHA-004, GACHA-005, GACHA-011 |

## 넣은 결함

```diff
 // Core/Gacha/GachaService.cs
-if (banner.HardPity > 0 && count >= banner.HardPity)
+if (banner.HardPity > 0 && count > banner.HardPity)
```

## 환경

| 항목 | 값 |
|---|---|
| 코드 | `1db01a0` + 위 변경 |
| OS / 런타임 | Windows 11 Pro 10.0.26300 / .NET SDK 10.0.402 |
| 데이터 | 실제 데이터 `b_standard` (3성 2.5%, 천장 90, 공시 실제 3성 2.79%) |

## 사전조건

- 천장 카운트 89 (마지막 3성 이후 89번 모집)

## 재현 절차

**A. 게임 화면 (개발 빌드) — 게임 화면 미실행, 절차만 적음**

1. 홈 → "QA 디버그 패널" → "천장 직전(89회)으로" (토스트 "다음 모집이 천장입니다.")
2. 돌아가기 → 홈 상단 "천장까지 1회" 확인
3. "1회 모집" → 결과 카드 확인

**B. 확률 검증기 (실행함)**

```
$ qa gacha-verify --banner b_standard --pulls 1000000
```

**C. 자동화 테스트 (실행함)**

```
$ dotnet test dotnet/Core.Tests
```

## 기대 결과

- 90번째 모집에서 3성 확정, 카드에 "천장" 표시, 천장 카운트 0.
- 100만 회 중 3성 사이 간격이 90회를 넘는 경우 0번.

## 실제 결과

- 90번째 모집에서 3성이 확정되지 않음 (테스트: `Expected: ThreeStar / But was: OneStar`).
- 100만 회 중 가장 긴 3성 간격 **91회**. 천장으로 나온 3성 2,821회가 모두 91번째에 나옴.

## 재현율

결정적(시드 고정). 천장 카운트 89에서 1회 모집하면 3성 기본 확률(2.5%)로 우연히 3성이 나오는 경우를 빼고 매번 재현. 확률 검증기는 시드 1 / 100만 회에서 1/1.

## 첨부

### 확률 검증기 출력 (결함 넣은 상태)

```
[b_standard] 상시 모집
  PASS  기본 등급 확률 — χ²=5.71 (자유도 2), p=0.0575
  PASS  ★★★ 캐릭터 분포 — χ²=2.33, p=0.3119
  PASS  ★★ 캐릭터 분포 — χ²=0.29, p=0.8671
  PASS  ★ 캐릭터 분포 — χ²=0.76, p=0.6823
  PASS  공시한 실제 3성 획득률 — 관측 2.758% vs 공시 2.79% (허용 ±0.071%)
  FAIL  천장 동작 — 가장 긴 간격 91회 / 천장 90회
  PASS  10연 2성 이상 보정 — 10연 100,000번 중 위반 0번
종합: 실패
```

### 자동화 테스트 실패 출력

## QA 메모: 실제 확률만 봤다면 놓쳤다

결함이 있어도 **"공시한 실제 3성 획득률" 검사는 통과**했습니다 (관측 2.758%, 허용 범위 2.79% ± 0.071% 안). 천장이 한 칸 밀려도 장기 평균 확률은 거의 변하지 않기 때문입니다. 이 결함은 **3성 사이 최대 간격**과 **89→90 경계값 TC**로만 잡혔습니다. 확률형 기능은 "평균"과 "경계" 둘 다 봐야 하는 이유입니다.

## 원인 / 수정 확인 (시연)

- 원인: 천장 비교에 `>`를 써서 카운트가 90일 때 확정이 걸리지 않음.
- 수정: `>=`로 되돌림 → 위 테스트 3개와 확률 검증기 모두 통과 (원래 코드에서 가장 긴 간격 90회).
