# DEMO-003 [미니게임] Perfect 판정 경계(중심 ±0.04)가 Good으로 판정됨

> **구분: 시연용 (일부러 넣은 결함)** — 실제 출시물의 버그가 아닙니다. [뮤테이션 스모크](../../scripts/mutation_smoke.py)의 "Perfect 판정 경계 미포함 (< 와 <= 혼동)" 변경을 코드에 넣은 상태에서 리플레이 도구·테스트를 돌린 출력입니다.

| 항목 | 내용 |
|---|---|
| 심각도 | Major — 진행은 되지만 판정이 기획(±0.04 포함)과 다르고 보상이 줄어듦 |
| 우선순위 | P0 — 보상(재화)에 바로 영향. TC 문서의 MINI-002 우선순위(P0)와 같게 둠 |
| 영역 | 미니게임 / 판정 |
| 관련 TC | MINI-002 |

## 넣은 결함

```diff
 // Core/MiniGame/TimingTapGame.cs  Judge
-if (d <= _cfg.PerfectHalfWidth + eps) return Judgement.Perfect;
+if (d < _cfg.PerfectHalfWidth) return Judgement.Perfect;
```

## 환경

| 항목 | 값 |
|---|---|
| 코드 | `1db01a0` + 위 변경 |
| OS / 런타임 | Windows 11 Pro 10.0.26300 / .NET SDK 10.0.402 |
| 설정 | 기본 `TimingTapConfig` (주기 1.6초, 중심 0.5, Perfect ±0.04, Good ±0.12) |

## 사전조건

- 막대 위치가 정확히 Perfect 경계(0.46)에 오는 시각에 탭. 주기 1.6초에서 t = 0.368초, 이후 1.6초 간격.

## 재현 절차

1. 아래 탭 기록으로 리플레이를 돌린다.

```
$ qa minigame-replay --taps 0.368,1.968,3.568,5.168,6.768,8.368,9.968,11.568,13.168,14.768
```

게임 화면에서는 미니게임 결과 화면의 "리플레이:" 줄에 이런 탭 시각 목록이 나옵니다. 사용자가 판정이 이상하다고 할 때 이 문자열만 받으면 위 명령으로 그대로 다시 돌려 볼 수 있습니다.

```

  t= 1.968s  위치 0.460  Good    콤보  2  +55
```

10탭 모두 Perfect → Good, **보상 72 → 36 보석**.

## 재현율

결정적. 같은 탭 기록이면 항상 같은 결과 (1/1, 리플레이는 시각만으로 계산하므로 기기·프레임과 무관).

## 첨부

### 자동화 테스트 실패 출력

```
  실패 PerfectBoundary(0.54d,Perfect)      [MINI-002]
     Expected: Perfect
  But was:  Good
```

### QA 메모: 왜 0.46은 테스트에서 통과했나

같은 TC의 `0.46` 케이스는 결함을 넣어도 **통과**했고 `0.54` 케이스만 실패했습니다. `0.5 - 0.46`과 `0.54 - 0.5`는 부동소수 오차 때문에 정확히 0.04가 아니고, 한쪽은 0.04보다 아주 조금 작게, 다른 쪽은 조금 크게 계산됩니다. 그래서 경계값 TC는 **양쪽 경계를 모두** 넣어야 하고, 원래 코드가 `eps`(1e-9) 여유를 두는 이유도 이것입니다. 리플레이의 `위치 0.460`은 소수 셋째 자리로 반올림해 보여 준 값입니다.

## 원인 / 수정 확인 (시연)

- 원인: 경계를 포함해야 하는 비교에 `<`를 쓰고, 부동소수 여유(`eps`)도 빠짐.
- 수정: `<= PerfectHalfWidth + eps`로 되돌림 → MINI-002 통과, 위 리플레이가 Perfect 10회·보상 72로 돌아옴.
