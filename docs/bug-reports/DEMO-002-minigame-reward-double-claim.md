# DEMO-002 [미니게임/재화] 끝난 판의 보상을 두 번 받을 수 있음

> **구분: 시연용 (일부러 넣은 결함)** — 실제 출시물의 버그가 아닙니다. [뮤테이션 스모크](../../scripts/mutation_smoke.py)의 "미니게임 보상 중복 수령" 변경을 코드에 넣은 상태에서 테스트를 돌린 출력입니다.

| 항목 | 내용 |
|---|---|
| 심각도 | Critical — 재화가 무한히 늘 수 있음 (경제 붕괴) |
| 우선순위 | P0 |
| 영역 | 미니게임 / 재화 |
| 관련 TC | MINI-010 |

## 넣은 결함

```diff
 // Core/GameSession.cs  ClaimMiniGame
-if (game == null || !game.IsFinished || game.RewardClaimed) return 0;
```

## 사전조건

- 미니게임 한 판(10탭)을 끝낸 상태. 보상 72 보석이 나오는 판.

## 재현 절차

1. 끝난 판에 대해 `ClaimMiniGame`을 호출한다 → 보석 +72.
2. **같은 판**에 대해 `ClaimMiniGame`을 한 번 더 호출한다.

게임 화면에서 이런 호출이 일어날 수 있는 경로의 예 (게임 화면 미실행): 결과 화면 진입 처리가 두 번 도는 경우(빠른 연타, 화면 전환 중 재진입), 네트워크 게임이라면 재시도 요청. 리포트에는 "어떤 경로든 같은 판을 두 번 정산하면 보석이 두 번 들어간다"는 규칙 수준의 재현을 먼저 적고, 화면 경로는 찾는 대로 덧붙입니다.

## 기대 결과

두 번째 호출은 0을 돌려주고 보석은 한 번만 늘어남.

## 실제 결과

두 번째 호출도 72를 돌려줌 (보석이 두 번 늘어남).

## 재현율

결정적. 1/1 (같은 입력이면 항상 재현).

## 첨부


## 원인 / 수정 확인 (시연)

- 원인: "이미 받은 판인지"(`RewardClaimed`) 검사가 빠짐.
- 수정: 검사를 되돌림 → MINI-010 통과.
- 같이 볼 것: 스테이지 첫 클리어 보상(STAGE-002)도 같은 유형(중복 지급)이라 함께 회귀 확인.
