# 체크리스트 (CL)

TC가 "규칙 하나를 정확히 확인"하는 문서라면, 체크리스트는 **빌드를 받았을 때 사람이 빠르게 훑는 목록**입니다. 항목마다 관련 TC를 적어 두어, 체크리스트에서 이상이 보이면 해당 TC로 내려가 자세히 확인합니다.

| 파일 | 언제 | 분량 | 항목 |
|---|---|---|---|
| [`build-smoke.csv`](build-smoke.csv) | 새 개발 빌드를 받자마자 | 10~15분 | 15 (턴제 3 포함) |
| [`outgame-release.csv`](outgame-release.csv) | 출시·업데이트 빌드 확정 전 | 반나절 | 30 (모집 9 · 재화 3 · 보상 4 · 스테이지 해금 4 · 세이브 4 · 보유 캐릭터 3 · 공통 3) |

## 열

| 열 | 내용 |
|---|---|
| `CL_ID` | `SMK-xx`(빌드 스모크), `REL-영역-xx`(릴리즈) |
| `영역` | 모집 · 재화 · 보상 · 스테이지 해금 · 세이브 · 보유 캐릭터 · 공통 |
| `확인 항목` | 눈으로 확인할 결과 한 줄 |
| `확인 방법` | 어디서 무엇을 누르는지. 디버그 패널(보석 지급, 천장 89회로 이동 등)을 적극 사용 |
| `관련 TC` | [`test-cases.csv`](../test-cases.csv)의 TC 번호. 비어 있으면 비고에 "TC 없음 → 추가 후보" |
| `자동 확인` | 이미 자동으로 확인되는 범위. `CI` = 관련 TC가 push·PR마다 통과 확인됨 / `자동 플레이` = 빌드 자동 플레이(`-qaAutoplay`)가 해당 화면을 지나며 확인 |
| `결과` | 빈칸. 실행할 때 `Pass` / `Fail` / `N/A` / `Block` |
| `비고` | 실패 시 이슈 번호, 경계값 메모 |

`자동 확인`이 있어도 체크리스트에서 지우지 않습니다. 자동화는 **규칙**을 확인하고, 체크리스트는 **그 빌드의 화면**에서 같은 결과가 보이는지 확인합니다 (UI 연결이 끊기는 결함은 규칙 테스트로 잡히지 않음).

## 구글 시트로 가져오기

1. 구글 시트 → 파일 → 가져오기 → 업로드 → CSV 선택
2. 구분자 "쉼표", "텍스트를 숫자·날짜로 변환" 끄기
3. `결과` 열에 데이터 확인(드롭다운: Pass, Fail, N/A, Block)을 걸고, 조건부 서식으로 Fail을 빨간색으로

파일은 UTF-8(BOM 없음), 줄바꿈 LF이며 쉼표가 들어간 칸은 큰따옴표로 감쌌습니다. 모든 행의 열 수가 같고, `관련 TC`의 번호가 모두 `test-cases.csv`에 있음을 Python `csv` 모듈로 확인했습니다.

빌드마다 시트를 복사해 `빌드 커밋 / 날짜 / 담당자`를 맨 위에 적어 두면, 어떤 빌드에서 무엇이 깨졌는지 이력이 남습니다.

## TC가 없는 항목 (추가 후보)

체크리스트를 쓰다 보니 TC로 덮이지 않은 확인 항목이 나왔습니다. TC를 바로 만들지 않고 비고에 남겨, 다음 TC 정리 때 반영합니다.

- 10연 보석 1,499 경계 (REL-GACHA-03)
- 보석 천 단위 표시 (REL-CUR-02)
- 보유 목록 정렬·미보유 표시 (REL-ROS-01), 홈 보유 수 표시 (REL-ROS-03)
- 출시 빌드에서 디버그 패널 제외 (REL-COM-01)
- 홈 "천장까지 N회" 표시 (SMK-06)

1,499 경계를 빼면 모두 화면 표시라 Unity PlayMode 테스트로 만들 항목입니다. 모집 기획 리뷰에서 나온 후보(천장 3성의 픽업 판정, 10연이 천장을 넘김, 10번째 장 천장 vs 보정)는 GACHA-016~018로 추가해 REL-GACHA-04·06의 관련 TC에 넣었습니다.
